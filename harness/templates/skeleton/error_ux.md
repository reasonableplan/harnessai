## {{section_number}}. 에러 처리 UX

### 에러 표시 방식
| 에러 유형 | 표시 방식 | 메시지 예시 |
|----------|----------|------------|
| 입력 검증 실패 | 인라인 (필드 하단) | `<예: "이메일 형식이 올바르지 않습니다">` |
| API 실패 (일시적) | Toast / Snackbar | `<예: "저장에 실패했습니다. 다시 시도해 주세요.">` |
| 인증 만료 | Modal 또는 페이지 이동 | `<예: 로그인 페이지로 redirect>` |
| 서버 에러 (500) | 전체 페이지 에러 | `<예: "일시적인 오류가 발생했습니다">` |
| 리소스 없음 (404) | 404 전용 페이지 | `<예: "페이지를 찾을 수 없습니다">` |
| 권한 없음 (403) | `<예: 홈으로 redirect / 접근 불가 안내>` | |

### Retry 전략
- **자동 retry**: `<예: 네트워크 에러 시 3회, 지수 백오프 1s → 2s → 4s>`
- **수동 retry**: `<예: 모든 API 실패에 "다시 시도" 버튼 제공>`
- **retry 불가**: `<예: 인증 에러(401), 입력 검증 에러(422) — 재시도 의미 없음>`

### 에러 바운더리 범위
- **전체 앱**: 예상치 못한 JS 에러 → `<예: "잠시 후 다시 시도해 주세요" + 새로고침 버튼>`
- **페이지 단위**: `<예: 상세 페이지 에러 → 목록으로 돌아가기 버튼>`
- **컴포넌트 단위**: `<예: 차트 렌더링 에러 → 빈 상태 표시, 나머지 페이지 정상 동작>`

### 백엔드 에러 코드 → UI 동작 매핑
| 백엔드 코드 | UI 동작 |
|------------|--------|
| `AUTH_001` | 로그인 페이지 redirect |
| `AUTH_002` | silent refresh 시도 → 실패 시 로그인 Modal |
| `AUTH_003` | 권한 없음 안내 (홈으로 이동) |
| `VALIDATION_001` | 인라인 에러 표시 (필드별) |
| `RESOURCE_001` | 404 페이지 또는 "항목을 찾을 수 없습니다" Toast |
| `RESOURCE_002` | 인라인 에러 "이미 존재하는 항목입니다" |
| `SERVER_001` | Toast "일시적 오류" + retry 버튼 |

### 로딩 상태 전략
- **Skeleton UI**: `<예: 목록/카드 첫 로딩 시>`
- **Spinner**: `<예: 버튼 클릭 후 제출 대기 시>`
- **Optimistic update**: `<예: 좋아요/삭제 즉시 반영 후 에러 시 롤백 / 없음>`

> 작성 가이드:
> - 백엔드 errors 섹션의 에러 코드와 1:1 매핑 필수
> - 사용자 노출 메시지는 기술 용어 없이 작성
> - Optimistic update 적용 범위를 구체적으로 결정 (이후 state.flow 구현에 영향)
